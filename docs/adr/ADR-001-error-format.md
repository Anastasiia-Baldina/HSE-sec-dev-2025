# ADR-001: Единый формат ошибок RFC 7807

Дата: 2025-10-15
Статус: Accepted

## Context
В текущей реализации ошибки возвращаются в разных форматах, что усложняет клиентскую обработку и может раскрывать внутренние детали системы. Необходим стандартизированный формат ошибок для всех эндпоинтов.

## Decision
Принять RFC 7807 (Problem Details for HTTP APIs) как единый формат для всех ошибок API. Все обработчики ошибок будут возвращать JSON с полями:
- `type`: URI идентификатор типа ошибки
- `title`: Человекочитаемое описание
- `status`: HTTP статус код
- `detail`: Конкретные детали ошибки
- `correlation_id`: Уникальный идентификатор для трассировки

## Alternatives
1. **Кастомный формат** - создание собственного формата, но это увеличивает сложность клиентов
2. **GraphQL ошибки** - избыточно для REST API
3. **Оставить как есть** - неприемлемо из-за рисков безопасности и сложности поддержки

## Consequences
**Плюсы:**
- Стандартизированная обработка ошибок клиентами
- Улучшенная безопасность (маскирование внутренних деталей)
- Упрощение отладки через correlation_id

**Минусы:**
- Небольшое увеличение размера ответов
- Требуется миграция существующих клиентов

## Security Impact
Снижает риски R5 (утечка деталей ошибок) и R10 (лик токенов в логах) из STRIDE. Соответствует NFR-02 и NFR-08.

## Rollout Plan
1. Реализовать middleware для преобразования всех ошибок
2. Добавить correlation_id в логи
3. Обновить документацию API
4. Протестировать все сценарии ошибок
